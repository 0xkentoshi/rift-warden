# RIFT // WARDEN

Интерактивная лаборатория нестабильных порталов для тестового задания MOX AI-first Developer 2.0.

[Открыть приложение](https://0xkentoshi.github.io/rift-warden/) · [GitHub](https://github.com/0xkentoshi/rift-warden) · [Проверки и деплой](https://github.com/0xkentoshi/rift-warden/actions)

Смотритель оценивает риск, стабилизирует разломы, отправляет наблюдателей и безопасно закрывает порталы. Пространственная сцена дополняется обычным реестром: все действия доступны без перемещения персонажа.

## Запуск

Нужен Node.js 24 LTS и npm. Проверено с установленными в рабочей среде зависимостями; lockfile включён. Секреты, API-ключи и backend не нужны.

```powershell
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (по умолчанию http://localhost:5173).

```powershell
npm test
npm run lint
npm run build
npm run preview
```

Production-файлы — в `dist/`; preview по умолчанию http://localhost:4173.
Это локальные адреса. Публичная версия доступна по ссылке в начале README.

## Проверка за минуту

1. Откройте Crimson Gate: риск **93**, рекомендация — стабилизировать.
2. Попробуйте отправить наблюдателя. Действие отклонено с объяснением и записью в истории.
3. Нажмите «Стабилизировать»: предпросмотр покажет энергию 94 → 79, стабильность 16 → 46, время 4 → 19 мин, риск **93 → 38**. Нажмите «Подтвердить» — данные, эффекты и счётчики обновятся.
4. Попробуйте закрыть: появится предупреждение о **3 существах**. Отмена сохраняет портал; подтверждение закрывает.
5. Посмотрите ЖУРНАЛ, СИСТЕМУ и AI WORKLOG.
6. СИСТЕМА → пустая лаборатория → восстановить демо.

## Управление

- WASD или стрелки — движение; физические клавиши работают и при русской раскладке.
- E — ближайший портал, если смотритель находится у подхода.
- Клик по арке или подписи — осмотр с любого расстояния.
- Escape — сначала отмена предпросмотра, затем закрытие панели. В открытой панели движение блокируется, Tab остаётся внутри.
- Реестр — все параметры, фильтры, открытие карточки.
- RU / EN — язык интерфейса и подписей; предпочтение сохраняется.
- Настройки / музыкальная нота — звук, громкость, управление, сброс демо.
- На телефоне под миниатюрой комнаты есть крупные кнопки порталов.

Браузер может разрешить звук только после первого нажатия. Мелодия зациклена; музыка не является зависимостью логики и тестов.

## Формула риска

Сумма факторов, ограниченная 100. В каждой группе берётся **один** подходящий порог.

| Фактор                                    | Баллы           |
| ----------------------------------------- | --------------- |
| Стабильность ≤20 / ≤40 / ≤60              | +35 / +25 / +10 |
| Энергия ≥90 / ≥75 / ≥60                   | +25 / +15 / +5  |
| Время до схлопывания ≤5 / ≤15 / ≤30 минут | +25 / +15 / +5  |
| Существ ≥6 / 1–5                          | +15 / +8        |
| Неопределённое состояние                  | +10             |

LOW 0–24; MEDIUM 25–49; HIGH 50–74; CRITICAL 75–100. Закрытый портал имеет риск 0.
ATTENTION в верхнем HUD считает HIGH и CRITICAL; очередь в СИСТЕМЕ также показывает MEDIUM и неопределённые порталы.

Стабилизация: +30 к стабильности (макс. 100), −15 к энергии (мин. 0), +15 минут.
Нельзя стабилизировать закрытый портал или портал со стабильностью ≥90.
Нельзя отправить наблюдателя при CRITICAL. Закрытие при наличии существ требует явного подтверждения.
Наблюдение записывает событие, но не выдумывает изменение телеметрии.
Время до схлопывания — показание, а не таймер реального времени.
Если показание уже равно 0, окно вмешательства истекло: разрешено только закрытие с обычным предупреждением о существах. Отрицательные значения не принимаются при загрузке.
Перед допустимым действием показывается точный прогноз из той же предметной функции, которая применяет изменения. Подтверждение повторно валидируется; короткая блокировка защищает от двойного действия. Подтверждённое предупреждение о существах сохраняется в аудите вместе с их числом.

## Архитектура

- `src/domain/` — независимые расчёт риска, валидация, действия, аудит, сводка и рекомендации.
- `src/data/labLayout.ts` — единственная карта сцены: 1672×941, арки, подходы, препятствия и огни.
- `src/game/` — масштабирование, коллизии, поиск ближайшего портала, профили эффектов.
- `src/components/game/` — фон, живые подписи, спрайт и один Canvas с эффектами.
- `src/components/ui/` — реестр, журнал, система, настройки, Worklog, fallback ошибки.
- `src/storage/` — проверка и миграция localStorage, восстановление после некорректных данных.
- `src/tests/` — предметные, геометрические и интеграционные тесты.

Одинаковый масштаб X/Y применяется ко всей сцене. При движении нормализуется диагональ, коллизии проверяются с подшагами. Если шаг блокируется, сохраняется свободная ось или движение проецируется на касательную наклонного края; каждый вариант повторно проверяет collision map и не увеличивает скорость. При отпускании клавиши позиция останавливается сразу; небольшой bob затрагивает только спрайт и тень. Персонаж смотрит по фактическому направлению движения. Эффекты учитывают reduced motion и паузу вкладки; Canvas обновляется не чаще 30 раз в секунду независимо от movement RAF.

Walkable map ограничена центральным кругом, шестью дорожками и ступенями. Лестницы вырезают разрешённый проход только в коллайдере своей арки; боковые камни остаются непроходимыми. Координаты обозначают ноги персонажа; у нижней центральной арки кладка перекрывает персонажа с учётом глубины.

Для визуальной отладки откройте `/?debug`: синие зоны — разрешённые маршруты, красные — препятствия, зелёные круги — интеракции. По умолчанию отладка выключена.

## Сохранение и ошибки

Данные, события, язык и звук сохраняются локально в браузере. Невалидный JSON, невозможные значения и дубликаты записей не роняют приложение. При запрете/переполнении localStorage появляется предупреждение; работа в памяти продолжается. Для ошибки рендера предусмотрен отдельный экран с перезагрузкой.

«Пустая лаборатория» оставляет журнал. «Восстановить демо» и сброс в настройках требуют подтверждения, возвращают шесть порталов, очищают историю и временные эффекты, ставят персонажа в центр. Язык и звук сохраняются.

## AI и ассеты

AI Worklog доступен по постоянной кнопке в интерфейсе. Роли автора/AI, ключевые запросы, решения, ошибки и ограничения описаны без придуманных метрик.
Ранние итерации исключены из учёта времени по просьбе автора. Токены не подсчитывались.

Чистый фон `src/assets/laboratory-clean.png` и спрайты `src/assets/warden-walk.png` созданы встроенным ImageGen. Референс и музыка предоставлены в исходном проекте. Суть запросов и происхождение — `docs/assets.md`. Шрифт Pixelify Sans с кириллицей включён локально вместе с OFL-лицензией; CDN не требуется.
Финальный фон v3 принят автором и зафиксирован по SHA-256 в [asset-lock-v3.md](docs/asset-lock-v3.md). Его геометрия больше не меняется. Риск управляет количеством частиц, скоростью, свечением и локальными всплесками; индикаторы существ берут реальное число из состояния (до трёх фигур и счётчик большой группы).

После полировки: LOW / MEDIUM / HIGH / CRITICAL используют 24 / 62 / 126 / 280 частиц соответственно, отдельные орбитальные движения, искры, shimmer и пульсацию. У HIGH/CRITICAL появляются искры на подходе; при близости смотрителя — короткий ping и усиление ауры. Световые якоря привязаны к 44 существующим огням, воздух содержит 110 слабых пылинок. Рама портала и фон не перемещаются: нестабильность меняет только магическое поле и свет. Закрытые порталы не получают активной ауры/частиц. Семантическая таблица реестра сохранена для доступности, визуально оформлена как записи с цветными печатями.

## Ограничения

- Локальное демо без авторизации, сервера и совместной работы.
- Окружение — иллюстрация. Движение, VFX, статусы, подписи и UI динамические; свет, нарисованный на кирпичах, остаётся частью арта после закрытия.
- Коллизии консервативные: стены, арки, мебель и перила непроходимы; за декорациями персонаж не ходит. Это не полноценная 3D-физика.
- Для сенсорного экрана предназначены карточки и реестр; виртуального джойстика нет.
- Доступные действия не открывают закрытые порталы; вернуть исходное состояние можно через демо-сброс.

## Публикация

Приложение можно размещать как статический сайт. Команда сборки: `npm run build`, каталог публикации: `dist`.
Для размещения в подпапке (например, GitHub Pages) используется относительный Vite base. HTML и ассеты не требуют роутера.
Workflow `.github/workflows/pages.yml` запускает тесты, lint и сборку на чистом Ubuntu с Node.js 24. При успешной проверке `main` публикуется в GitHub Pages. Pull request проходит проверки без публикации. Настройка Pages: Source → GitHub Actions.
Используется [официальный workflow GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
Исходники для репозитория должны включать `src`, `public`, `docs`, конфигурации, `package.json` и `package-lock.json`. Не включайте `node_modules`, `dist`, архивы прежних патчей и бэкапы.
