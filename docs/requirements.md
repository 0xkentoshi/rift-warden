# Проверка по исходному ТЗ MOX
Выбран вариант «AI-first Developer 2.0 — Лаборатория нестабильных порталов».
Исходное задание предоставлено автором в этой сессии. Вариант с привидениями — альтернативное задание, не часть продукта.

| Требование | Где реализовано |
| --- | --- |
| Список с названием, миром, энергией, стабильностью, временем, существами, статусом | РЕЕСТР ПОРТАЛОВ; фильтры, сортировка по риску |
| Карточка: риски, история изменений, рекомендуемое действие | Клик по порталу / карточке / строке реестра либо E у подхода |
| Понятная формула | Карточка → «Как считается риск?»; README |
| Минимум 3 действия | Стабилизировать, отправить наблюдателя, пометить неопределённым, закрыть |
| Ограничения и предупреждение | validateAction; подтверждение при существах; отклонения записываются |
| Журнал всех действий | ЖУРНАЛ, дата/время, статус, причина отказа, риск до/после |
| Итоговая сводка и приоритеты | СИСТЕМА, метрики и отсортированная очередь |
| Пустой список | СИСТЕМА → пустая лаборатория; восстановление демо |
| Критический риск | Crimson Gate: 93 |
| Запрещённое действие | Наблюдатель для Crimson Gate до стабилизации |
| Изменение риска | Стабилизация Crimson Gate: 93 → 38 |
| Несколько операций в журнале | Интеграционные тесты и браузерная проверка |
| AI Worklog внутри приложения | Постоянная кнопка AI WORKLOG |
| README и QA | README.md, docs/qa-checklist.md |
| Минимум 3 теста | Автотесты src/tests |
| GitHub и публичная ссылка | [Репозиторий](https://github.com/0xkentoshi/rift-warden), [приложение](https://0xkentoshi.github.io/rift-warden/), автоматические проверки перед деплоем |

Пожелания из handoff учитываются как дизайн и инженерные требования. В случае конфликта приоритет у исходного тестового задания.
